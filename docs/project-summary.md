# leetX 项目总结

## 一、目标与背景

leetX 是一个**本地优先的刷题记录浏览器扩展**（Manifest V3，Chrome/Edge），解决的核心问题是：刷题过程中每次提交的代码和判题结果散落在力扣/洛谷的历史页面里，无法高效回顾「这道题我从 WA 到 AC 经历了什么」。

扩展在题目页**自动采集**提交代码与判题结果，按可配置的时间窗口（默认 90 分钟滚动间隔）把同题连续提交聚合成一条刷题记录，并提供三栏工作台：历史记录、提交时间线、代码对比 + AI 分析。

设计上的关键立场：

- 所有数据存本地 IndexedDB，不自建后端
- 核心采集链路只观察用户可见页面，**不依赖站点私有 GraphQL/接口**，降低网站改版、风控和商店审核风险
- AI 分析只在用户明确点击时触发，费用可控

## 二、使用的 AI 工具及模型

- **开发协作**：Kimi Code CLI（Kimi 模型），以对话 + 工具调用的方式直接读写代码、跑测试、构建发布【具体模型版本待确认；如过程中还用过 Cursor/ChatGPT 等其他工具，请补充】
- **产品内嵌**：扩展的 AI 分析功能走用户自配置的 OpenAI 兼容 API（Base URL + API Key + 模型名），模型由使用者在设置里自行选择

## 三、选择的原因【待确认/补充】

- 浏览器扩展（MV3 Service Worker、Content Script 隔离世界、host permission）属于冷门且文档分散的领域，AI 能快速给出符合平台约束的方案，避免大量试错
- 站点适配器（力扣/洛谷的 DOM 选择器、Monaco 编辑器读取）是大量琐碎、模式化的工作，适合 AI 承担
- 项目需要高频的「看截图 → 改交互」UI 迭代，AI 配合截图反馈的迭代速度远快于手工调整样式

## 四、与 AI 的分工

- **人**：产品决策与边界把控（要不要某个功能、输出长什么样）、逐轮视觉验收（截图反馈）、关键取舍拍板（如「只要最小改动 diff，不要其他分析」）、最终发布确认
- **AI（Kimi Code）**：架构方案设计（`plan.md` 的完整落地计划：采集策略、聚合算法、数据模型、AI 任务队列、权限最小化）、全部编码实现、单元测试（78 个用例）、构建与 GitHub Release 发布、设计文档撰写（如 Notion 导出 spec）
- 流程上采用 skills 驱动的规范：先头脑风暴定边界 → 写实施计划 → 分阶段执行 → 测试验证后才声明完成

## 五、核心挑战与解决方案

1. **代码采集可靠性**：Content Script 运行在隔离世界，拿不到 Monaco/CodeMirror 编辑器对象 → 注入最小 MAIN-world bridge（带 nonce 校验、只暴露 `GET_EDITOR_SNAPSHOT`）；读取按 textarea → Monaco → CodeMirror → 渲染文本多级降级，**禁止按可视行 DOM 拼接**（虚拟滚动会漏行）
2. **提交后立即关页**：提交瞬间先落库 `pending` 节点保住代码，判题结果保持「待补齐」，下次访问补齐或手工修正——宁可状态不完整也不静默丢数据
3. **MV3 Service Worker 随时休眠**：AI 请求等长任务不依赖内存状态，先落库 Analysis + AiJob（带 lease），靠 `chrome.alarms` 唤醒恢复，幂等键防重复扣费
4. **记录聚合正确性**：采用「相邻提交滚动间隔」而非固定截止时间；补录旧节点/改窗口时做局部重聚合，且在一个 IndexedDB 事务内完成，保留用户手工锁定
5. **AI 输出的可用性**：经历了几轮演进——最初模型输出长文分析（题意/思路/复杂度），噪音大 → 收紧 prompt 只返回 `{code, changes:[{code, reason}]}` 的最小改动格式 → 前端渲染为红绿 diff，reason 匹配不到改动行就直接丢弃不展示。这是「用结构化约束 + 前端容错」治理模型不稳定输出的典型例子
6. **隐私与安全**：API Key 默认只存 `chrome.storage.session`；AI 域名按精确 origin 动态申请 host permission；模型输出经 Zod 校验、禁止 raw HTML、永远不作为扩展命令执行

## 六、项目结果

- 已发布 **v0.2.0**（GitHub Releases 分发 zip）：两站采集、会话聚合、时间线、行级 Diff、AI 最小改动分析（红绿 diff + 行内解释冒泡开关）、9 种语言语法高亮
- 工程质量：23 个测试文件 / 78 个用例全绿，`npm run build` 稳定产出 MV3 包
- 完成了阶段 0（采集可行性）到阶段 2/3（AI 分析）的核心路径；Notion 导出功能已完成设计稿待实施
