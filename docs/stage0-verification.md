# 阶段 0 人工验收记录（采集可行性）

构建命令：`npm run build`。在 Chrome 或 Edge 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，加载 `.output/chrome-mv3`。

自动验证已完成：Vitest 共 10 个测试文件、20 个测试全部通过，Chrome MV3 生产构建成功。真实站点检查尚待在本地浏览器完成。

每个平台至少验证 2 道题和 2 种语言。建议使用 leetcode.cn 的“两数之和”“合并两个有序链表”，以及洛谷的 P1001、P1042。

## 每题检查项

| # | 场景 | 操作 | 预期 |
|---|---|---|---|
| 1 | 按钮提交 | 点击“提交”或“提交评测” | Popup 和工作台出现该题记录；优先显示 `captureMethod=editor-model`；代码与编辑器一致 |
| 2 | 快捷键提交 | 编辑器内按 Ctrl/Cmd+Enter | 捕获一次且仅一次 |
| 3 | 判题终态 | 等待评测完成 | 节点 verdict 更新为正确终态，rawVerdict 保留站点原文 |
| 4 | 降级读取 | 临时禁用 pageBridge 的 Monaco 分支后重新加载 | 使用 `rendered-code`，或记录 `code-snapshot-missing` 异常，不能静默成功 |
| 5 | SPA 切题 | 在站内直接跳转到另一题并提交 | 新记录 problemKey 正确，无串题 |
| 6 | 重复提交同代码 | 5 秒内连续提交两次 | 幂等去重后仅保留一条捕获 |
| 7 | 间隔再提交 | 超过 5 秒后提交相同代码 | 生成第二个提交节点 |
| 8 | 提交后关页 | 提交后立即关闭标签页 | 代码快照保留，verdict 保持 pending |
| 9 | 异常可见 | 模拟选择器失效或无法识别页面 | Popup 的采集异常区域出现明确 reason |
| 10 | 多次提交分组 | 同一道题连续提交多次 | 工作台左侧只有一条题目记录，中栏展示多个提交节点 |
| 11 | 代码与分析 | 切换不同提交节点 | 右栏同步显示当前代码、与上次对比和确定性的本地采集分析 |
| 12 | 记录总结 | 打开具有多个节点的记录 | 顶部总结准确反映提交次数、判题演进和代码变化，不显示伪造的 AI 结论 |

## Go/No-Go 判定

Go：力扣与洛谷的题目标识、完整代码、提交动作和判题终态均可稳定采集；失败路径有明确 issue；同题多次提交能在工作台正确分组展示。

需要修正：若仅为选择器或判题文案不匹配，只修改 `src/adapters/*/selectors.ts` 和对应 `verdict.ts`，随后重新运行 `npm test` 与 `npm run build`，并在备注中记录。

No-Go：任一平台完整代码无法稳定读取，包括降级路径；或判题终态无法与提交关联。此时返回 `plan.md` 第 5 节重新评估采集策略，再决定是否进入阶段 1。
